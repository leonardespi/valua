# E0301 — Assignment to `<const>` variable

## Description

A variable declared with the `<const>` attribute in Lua 5.4/5.5 is a compile-time constant. Assigning to it is a compile error. valua enforces this statically, mirroring the behavior of the standard Lua compiler.

## Triggering example

```lua
local x <const> = 42
x = 99  -- E0301 fired here
return x
```

## Diagnostic

```
error[E0301]: assignment to const variable `x`
  ┌─ input.lua:2:1
  │
1 │ local x <const> = 42
  │       - declared as const here
2 │ x = 99
  │ ^ assignment to const variable `x`
  │
  = note: `x` was declared with <const>; Lua 5.4 treats this as a compile-time constant
  = help: Remove the assignment or remove the <const> attribute from the declaration
```

## Justification

The `<const>` attribute is part of `L_{5.5}^{nativo}` (the natively transpilable subset). valua handles it by stripping the attribute in emitted code (plain `local`). Enforcing the const constraint statically is correct because:

1. The transpiled output has no `<const>` — allowing mutation in the source but not in the emitted code would silently change program semantics.
2. The standard Lua 5.4 compiler rejects mutation of `<const>` variables, so any source that triggers E0301 is already an error in the reference implementation.

See PRD §5.1.

## Remediation

- Remove the assignment that triggers the error.
- If mutation is intentional, remove `<const>` from the declaration.
