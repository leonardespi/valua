# E0102 — Integer overflow semantics not portable

## Description

Lua 5.4 has a 64-bit integer type with wrapping overflow semantics (`math.maxinteger + 1 == math.mininteger`). LuaJIT has no integer type; all numbers are IEEE 754 doubles, which silently round large integers and do not wrap.

valua fires E0102 when it detects a literal equal to `math.maxinteger` (`9223372036854775807`), which is the conservative static trigger for this class of portability issue.

## Triggering example

```lua
local max = 9223372036854775807  -- E0102 fired here
local overflow = max + 1
return overflow
```

In Lua 5.4: `overflow == math.mininteger` (wraps).  
In LuaJIT: `overflow == 9223372036854775808.0` (rounds to nearest double; no wrap).

## Diagnostic

```
error[E0102]: integer overflow semantics differ between Lua 5.4 and LuaJIT
  ┌─ input.lua:1:13
  │
1 │ local max = 9223372036854775807
  │             ^^^^^^^^^^^^^^^^^^^ integer overflow semantics differ between Lua 5.4 and LuaJIT
  │
  = note: this literal equals math.maxinteger; Lua 5.4 wraps on overflow but LuaJIT uses IEEE 754 doubles
  = help: Use bit.* operations on the bit pattern explicitly, or accept double-precision semantics
```

## Justification

Integer overflow behavior is observable at the boundary `math.maxinteger`. Once a program relies on wrapping semantics (e.g., hashing, checksums, bit-packing), translating it to a floating-point target silently changes its results. The impossibility theorem (PRD §5.2, Anexo A) shows this cannot be fixed by a static transformation without runtime overhead that changes the semantics of every arithmetic operation. See PRD §5.2.

## Remediation

- If the code uses 64-bit wrapping arithmetic intentionally (hashing, crc), rewrite to use `bit.*` operations which work on 32-bit values in LuaJIT.
- If the code happens to use `math.maxinteger` as a sentinel value (not for arithmetic), replace it with a different sentinel that is representable as a double.
- If you do not target LuaJIT and are only targeting Lua 5.1, verify the arithmetic is within double-representable range (< 2^53).
